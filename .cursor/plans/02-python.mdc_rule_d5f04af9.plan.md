# План: `.cursor/rules/02-python.mdc`

## Summary

Создать правило Cursor для Python-кода проекта email2telegram: оно должно подключаться при работе с файлами в `src/` и фиксировать стиль, который уже виден в [src/main.py](src/main.py), [src/imap_client.py](src/imap_client.py) и соседних модулях.

## Текущий контекст

- Все `.py` лежат только в [`src/`](src/) (10 модулей); `pyproject.toml` / Ruff / mypy в репо нет.
- Уже принято: `from __future__ import annotations`, аннотации возвращаемых типов (`-> None` и т.д.), смесь `typing.List`/`Tuple` и современных union (`int | None`), `logging` для ошибок/событий, локальные импорты вида `from imap_client import ...` (запуск как `python src/main.py` — каталог скрипта в `sys.path`).
- Версия: **Python 3.12+** (уже в [01-core.mdc](.cursor/rules/01-core.mdc)).

## Предлагаемое решение

Новый файл с YAML frontmatter:

- **`description`**: кратко — соглашения по Python для `src/` (email2telegram).
- **`globs`**: `src/**/*.py` — правило не дублирует всегда включённое ядро, а активируется при правках Python.
- **`alwaysApply`**: `false`.

Содержание правила (кратко, ~40–55 строк, один фокус — Python, без дублирования команд/README из `01-core`):

1. **Версия и модульность** — 3.12+, новые модули в `src/`, не ломать схему импортов (соседние модули без пакетного префикса).
2. **Первые строки файла** — в новых/существенно меняемых файлах сохранять `from __future__ import annotations` как в существующих модулях.
3. **Типизация** — аннотации для публичных функций и методов; для optional допускать и `X | None`, и типы из `typing` там, где так уже сделано рядом.
4. **Ошибки и логи** — для рабочего кода предпочитать `logging` вместо `print`; конфигурация логов остаётся в точке входа (`main`), не размазывать `basicConfig` по библиотечным модулям без нужды.
5. **Зависимости** — новые сторонние пакеты только через [requirements.txt](requirements.txt) с явной мотивацией; не раздувать стек.
6. **Секреты** — не хардкодить; только env / `.env` (без повторения длинного текста из `01-core`, одна строка-напоминание).
7. **Согласование с кодом** — перед изменениями смотреть соседние файлы в `src/` и выравнивать стиль (имена, структура, уровень комментариев).

Опционально одна мини-секция **async** — в проекте есть `async` в `main.py` для telegram job queue; указать: не блокировать event loop синхронным I/O без необходимости (у вас IMAP в job — кратко «сохранять текущую модель: тяжёлая работа вне хендлеров / в job»).
